# Reconciliation

Preflight owns recursive graph traversal. It checks the reviewed owned payload, resolves each overlay binding, detects stable-ID and canonical-path cycles, enforces depth 32, and flattens execution as the base or fork workflow followed by semantic deltas from inner to outer. Inner maintenance stops propagate unchanged.

Reconciliation stays targeted to one semantic or provenance decision. Overlay source drift may be accepted, rejected, marked ambiguous, or identified as an absorbed delta. Cached compatibility decisions bind the source fingerprint, reviewed owned payload, and selected execution role and delta path. Source trees remain read-only; top-level aliases resolve to their canonical root, clone-local version-control metadata is excluded from fingerprints, and source-internal symlinks are rejected. Local reconciliation reports the identity derived from `SKILL.md` bytes while retaining the full-directory effective checkpoint. Customization sources use their recursively checked effective fingerprint and pass the matching base-to-inner execution plan to semantic review instead of exposing a raw directory hash or thin dispatcher. Direct overlay payload edits route to `skill-overlay`; accepted maintenance refreshes the reviewed fingerprints atomically, preserving portable artifact modes, before preflight reruns.

A fork is a runtime leaf. Reconciliation verifies its reviewed owned payload, requires the snapshot directory and diff beneath reserved `provenance/`, checks their fingerprints, excludes the same version-control metadata from fingerprint and reconstruction inputs, rejects symlinks, applies the unified diff to the snapshot directory, and requires the result to reproduce the complete independent workflow payload. Fork payload or provenance drift routes to `skill-fork`.

Fork tracking drift, unavailability, and invalid optional tracking state are advisory. Adoption or rebase is an explicit maintenance action. Forking an overlay chain first reviews a materialized base-plus-deltas snapshot and records both the chain effective fingerprint and concrete snapshot fingerprint. Changing either materialization fingerprint requires fresh review time and evidence.
